# Three attack modules, stdlib concurrency layer, and shared test infrastructure

The change adds HTTP/2 request smuggling, web cache poisoning, and API abuse scanner modules to the ATOMIC framework, alongside a stdlib-only concurrency layer (connection pool, rate limiter, thread-pool-based dispatcher and scan worker pool) and code quality improvements (exception hierarchy, shared test fixtures, enhanced type hints on BaseModule). All three modules follow the existing BaseModule/`_emit_signal` pattern and are wired into the CLI and engine registry. The concurrency infrastructure replaces a prior httpx-based `async_requester.py` with a threading/concurrent.futures implementation that avoids external dependencies.

**Watch for:** The H2 smuggling module disables SSL verification entirely (confirmed). The `_is_poisoned` heuristic in the smuggling module has high false-positive risk because it triggers on common HTTP error responses like "400 Bad Request" (confirmed). The new exception hierarchy is defined but not integrated into any existing or new code paths — nothing raises or catches these exceptions yet (confirmed).

## High-level view

The three attack modules implement their respective detection techniques and register cleanly in the engine and CLI. H2 smuggling uses raw sockets for protocol-level testing, cache poisoning uses canary-based cache verification, and API abuse combines rate-limit probing with BOLA/BFLA/mass-assignment checks. The smuggling module's detection heuristic conflates generic HTTP errors with evidence of desync, and the BOLA/mass-assignment checks have structural false-positive gaps.

The concurrency layer provides `ConnectionPool`, `RateLimiter`, `AsyncRequestDispatcher`, and `ScanWorkerPool` using only stdlib threading primitives. Nothing in the framework currently instantiates or integrates these components for actual scan execution — they're building blocks without a consumer. The worker pool fails open when the rate limiter errors.

The code quality work introduces an `EngineProtocol` type on `BaseModule`, a custom exception hierarchy in `utils/exceptions.py`, and a shared `tests/fixtures.py`. The exception hierarchy is purely declarative — no production code raises or catches any of these exceptions. The shared fixtures module is not imported by any of the new test files; they still define their own inline mocks.

## H2 smuggling via raw sockets and SSL bypass

`_raw_send` unconditionally disables TLS verification:

```python
ctx = ssl.create_default_context()
ctx.check_hostname = False
ctx.verify_mode = ssl.CERT_NONE
```

There's no configuration hook to enable verification when scanning production targets where MITM detection matters. Silently accepting any certificate means the scanner itself is vulnerable to interception of its probe traffic — an attacker on the network path could observe smuggling payloads and responses.

The `_is_poisoned` detection heuristic checks for strings like "Bad Request", "Method Not Allowed", and "403 Forbidden" in the response. Since the module sends deliberately malformed HTTP, almost any well-behaved server will return a 400 for the initial probe. The follow-up "normal" request (intended to detect response queue poisoning) connects on a *new* socket each time — it never reuses the connection from the poisoned request. The two-request correlation pattern doesn't actually share state, and the heuristic triggers on independently-arriving error responses.

The `_test_websocket_upgrade_smuggling` check for `b"101" in resp` could match on content containing the string "101" anywhere (e.g., "HTTP/1.1 101" or "Error code 101" in a page body).

## Cache poisoning: fixed sleep and TTL gap

The `time.sleep(0.3)` between poison and verify requests is a fixed delay rather than adaptive to actual cache TTL. If the cache has sub-second TTLs (edge CDN micro-caching), the canary may expire before verification. This limits detection of short-TTL cache poisoning scenarios.

## API abuse module: rate limiting and authorization probing

The rate limit bypass test makes 10 sequential requests to trigger rate limiting, then rotates headers. If the target has rate limits >10 req/s (common for APIs), the test never triggers the limit and returns early. The test also cannot distinguish between "rate limit bypassed" (the header trick worked) and "rate limit expired during header rotation" (natural cooldown).

BOLA detection reports 0.70 confidence at HIGH severity for any 200 response with >50 bytes on a neighbouring ID. Many APIs return structured error responses (e.g., `{"error": "not found"}`) that exceed 50 bytes with status 200. The module doesn't compare response structure between the original and probed ID to verify actual data leakage.

Mass assignment detection checks `field_name in str(resp_data)`. This string-in-string check matches field names appearing in error messages ("field 'role' is read-only") as well as in successful assignments, creating false positives.

## Concurrency layer: fail-open rate limiting

The `ScanWorkerPool._execute_single` method swallows rate-limiter failures silently:

```python
if self._rate_limiter is not None:
    try:
        acquire = getattr(self._rate_limiter, "acquire", None)
        if acquire is not None:
            acquire()
    except Exception:
        pass
```

If the rate limiter raises (pool closed, internal error), the task proceeds without throttling. This is fail-open behavior — under failure, the scanner removes its own safety controls. Nothing in the codebase currently wires these components together, so the risk is latent, but the pattern will be problematic when integration happens.

`ConnectionPoolManager.get_session()` raises `RuntimeError` rather than using the new `ConfigError` from the exception hierarchy. `ConnectionPool.acquire()` raises stdlib `TimeoutError` and `RuntimeError` rather than the new `NetworkError` subclasses — the new exception hierarchy isn't used even in the new code that would benefit from it.

## Exception hierarchy and shared fixtures: defined but unused

No code in this diff raises or catches any exception from `utils/exceptions.py`. The attack modules catch bare `Exception` and suppress errors. The hierarchy will drift from actual error patterns without integration.

`tests/fixtures.py` provides `MockEngine`, `MockRequester`, `MockResponse` with factory functions. The new test files (`test_h2_smuggling_module.py`, `test_cache_poisoning_module.py`, `test_api_abuse_module.py`) each define their own `_MockEngine` class inline. The DRY objective is architecturally prepared but not executed in this change.
